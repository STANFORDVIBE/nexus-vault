# Nexus Vault — архитектура

Рабочий документ. Описывает принятые решения; меняется вместе с кодом.

## 1. Общая схема

```
┌──────────────── WebView (React) ────────────────┐
│  UI, формы, навигация, состояние экрана          │
│  НЕТ: ключей, крипты, доступа к БД и ФС          │
└───────────────┬─────────────────────────────────┘
                │ Tauri IPC: только явные команды
┌───────────────▼──────────── Rust ───────────────┐
│ commands/  — тонкий слой IPC, валидация входа    │
│ core/      — сессия хранилища (Locked/Unlocked)  │
│ crypto/    — KDF, AEAD, envelope, генератор      │
│ database/  — SQLite, миграции, репозитории       │
│ backup/    — формат .nexus, автокопии            │
│ platform/  — трей, буфер обмена, автоблокировка  │
└───────────────┬─────────────────────────────────┘
                ▼
        %APPDATA%\<app-id>\vault.db, vaults\*.nexusvault
        + vaults.json (реестр хранилищ)
```

Граница доверия — IPC. Всё, что выше неё, считается потенциально скомпрометированным
(XSS в WebView), поэтому:

- Vault Key и KEK живут только в Rust, в обёртках `zeroize`/`secrecy`.
- Пароль записи по умолчанию в JS не отдаётся: копирование делает Rust по `item_id`
  (`copy_item_field(id, "password")`). В JS пароль попадает только по явному «Показать»
  и в форму редактирования.
- Мастер-пароль передаётся одной командой (`unlock` / `create_vault`) и сразу
  затирается в Rust; на фронте поле очищается после отправки.
- Tauri capabilities: без `fs`, `shell`, `http`. Плагины — только нужные
  (dialog для выбора файла бэкапа, autostart, global-shortcut, notification,
  single-instance, opener для http(s)-ссылок, updater — вызывается только из Rust). Буфер обмена — крейт `arboard` в Rust.
  CSP строгая, без внешних источников.

## 2. Криптография

Только проверенные крейты: `argon2`, `chacha20poly1305` (XChaCha20-Poly1305),
`rand`/`getrandom` (OS CSPRNG), `zeroize`, `secrecy`.

```
master password ──Argon2id(salt, params)──► KEK (32 B)
KEK ──XChaCha20-Poly1305──► расшифровка envelope ──► Vault Key (32 B, случайный)
Vault Key ──XChaCha20-Poly1305──► payload каждой записи и имя каждой папки
```

- Salt (16+ B) и параметры Argon2id (m, t, p) хранятся в `vault_meta`, поэтому их можно
  усиливать без потери старых хранилищ. Стартовые параметры подбираются бенчмарком
  на целевой машине (ориентир 0.5–1 с на разблокировку, память ≥ 64 MiB).
- Nonce — 24 случайных байта на каждое шифрование. Для XChaCha это безопасно и не требует
  счётчиков.
- AAD (связанные данные): `nexus-vault/v1/item/{vault_id}/{item_id}/{type}`, для папок
  `…/folder/{vault_id}/{folder_id}`, для ключа `…/envelope/{vault_id}`. Нельзя подменить
  или переставить шифротексты между записями — расшифровка упадёт.
- Открытый текст дополняется пробелами до кратного 64 байтам (размер не выдаёт длину).
- Смена мастер-пароля = перешифровка только envelope Vault Key (записи не трогаются).
- `crypto_version` в каждой строке → поддержка старых форматов при обновлениях.
- Неверный пароль определяется ошибкой аутентификации envelope; отдельного хеша пароля
  в базе нет.
- Второй конверт `key_envelopes.id = "hello"`: Vault Key под ключом из подписи Windows
  Hello (`platform/hello.rs`, `core/vault.rs`). Первые 32 байта `wrapped_key` — challenge.

Типы записей: `login`, `secure_note`, `card`, `identity` (enum `ItemPayload`, serde
`{type, payload}`). Новые поля добавляются с `#[serde(default)]`, старые записи читаются.
У любого типа есть `fields` — свои поля, скрытые маскируются как пароль. Дату смены пароля
(`password_changed_at`) ставит бэкенд — по ней проверка паролей находит старые.
Историю паролей (`password_history`, до 10 штук, новые сверху) тоже ведёт только бэкенд:
то, что прислал клиент, игнорируется, в форму редактирования она не отдаётся, старый пароль
показывается или копируется по одному (`history:<n>`).

Картинки в заметках (`core/attachments.rs`) — отдельная таблица `attachments`, по строке
на картинку: `mime-длина | mime | байты`, зашифровано Vault Key с AAD
`nexus-vault/v1/attachment/{vault_id}/{item_id}/{attachment_id}`. В тексте заметки —
ссылка `![…](attachment:<id>)`. При разблокировке картинки не расшифровываются: только когда
заметку открывают (`get_attachment` отдаёт сырые байты, WebView показывает их через `blob:`).
Тип определяется по сигнатуре байтов (PNG, JPEG, WebP, GIF; SVG нельзя — в нём бывают скрипты).
Картинки, на которые больше не ссылается ни одна заметка, удаляются при разблокировке —
не при редактировании, чтобы Ctrl+Z в редакторе мог вернуть удалённую ссылку. Удаление
заметки навсегда удаляет и её картинки (`ON DELETE CASCADE`).

Бэкап `.nexus` версии 3 содержит картинки как есть, отдельным блоком после JSON (в версии 2
они лежали в JSON в hex и занимали вдвое больше места); файлы версий 1–2 по-прежнему
восстанавливаются. Копия больше 2 ГБ не создаётся — восстановление читает файл целиком.
Автокопия пишется, только если хранилище изменилось: отпечаток (SHA-256 по id, nonce
и открытым флагам строк) сравнивается с сохранённым при прошлой копии.

## 3. База данных

`rusqlite` с вшитым SQLite (`bundled`): синхронный, предсказуемый, нормальные транзакции.
Доступ через один `Mutex<Connection>` в состоянии приложения — для локального
однопользовательского приложения этого достаточно.

Миграции — SQL-файлы в `src-tauri/migrations/`, вшиваются в бинарник, применяются
по порядку в транзакции, учёт в `schema_migrations`.

Что лежит в открытом виде (и почему):

| Поле                                        | Открыто | Причина                                                                      |
| ------------------------------------------- | ------- | ---------------------------------------------------------------------------- |
| `id`                                        | да      | случайный UUIDv4, ничего не говорит о содержимом                             |
| `item_type`                                 | да      | фильтры по разделам без расшифровки; раскрывает только число паролей/заметок |
| `folder_id`, `is_favorite`, даты            | да      | сортировка и разделы; не раскрывают содержимого                              |
| название, URL, логин, пароль, заметки, теги | **нет** | только в зашифрованном payload                                               |
| имена папок и тегов                         | **нет** | шифруются тем же Vault Key                                                   |

Теги хранятся только внутри зашифрованного payload записи, отдельных таблиц `tags`
и `item_tags` нет: связи «запись — тег» в открытом виде раскрывали бы структуру
хранилища. У `attachments` открыты только id, id заметки и дата; размер шифротекста
примерно равен размеру картинки.

Несколько хранилищ: `core/registry.rs` ведёт `vaults.json` (id, имя, путь, активное).
Одновременно открыто одно; переключение блокирует текущее.

## 4. Поиск

FTS по открытому тексту запрещён. При разблокировке Rust расшифровывает «сводки»
записей (название, сайт, логин, теги) в память, поиск идёт по ним в Rust.
10 000 записей — это единицы мегабайт и миллисекунды на поиск. При блокировке индекс
затирается.

## 5. Блокировка

`core::state::AppState` держит `Option<UnlockedVault>`; `None` — заблокировано. Lock:

1. Vault Key, индекс и кеши затираются (`zeroize` при `Drop`).
2. Rust шлёт событие `vault-locked`, фронт сбрасывает сторы, закрывает диалоги
   и уходит на Unlock Screen.
3. Таймер очистки буфера обмена срабатывает досрочно, если в буфере ещё наш секрет.

Ограничение честно фиксируем: JS-строки не затираются гарантированно, а ОС может
сбросить память в своп. Мы минимизируем время жизни секретов, а не обещаем
защиту от форензики.

## 6. Фронтенд

- React 19 + TypeScript + Vite, Tailwind CSS v4, shadcn/ui (Radix), Lucide.
- Роутинг: React Router. Состояние: Zustand (без `persist` для любых данных хранилища).
- Формы: React Hook Form + Zod; те же ограничения повторно проверяются в Rust.
- Весь доступ к Rust — через `src/services/*` (типизированные обёртки над `invoke`).
  Компоненты `invoke` напрямую не вызывают.
- Несекретные настройки хранятся в таблице `settings`. Исключение — тема: она нужна до
  разблокировки (экраны Onboarding/Unlock), поэтому лежит в `localStorage`. Больше туда
  ничего не пишется.

### Дизайн-система

- Токены цветов — CSS-переменные в `src/styles/globals.css`: светлая тема на `:root`,
  тёмная на `.dark` (по умолчанию). Имена shadcn сохранены; золотой акцент — это
  `primary`/`brand`, а `accent` у shadcn — нейтральный цвет наведения.
- Радиусы: 8 px — кнопки и поля (`rounded-md`), 10 px — карточки (`rounded-lg`).
  Анимации 150 мс, при `prefers-reduced-motion` отключаются.
- Шрифт Inter вшит в приложение (`@fontsource-variable/inter`), сеть не нужна.
- Базовые компоненты — `src/components/ui` (shadcn + свои: `PasswordInput`,
  `SegmentedControl`). Общие — `src/components/common`, каркас — `src/components/layout`.
- Тема: `src/store/theme.ts` (Тёмная / Светлая / Системная), синхронизирует цвет
  заголовка окна Windows.

## 7. Тесты

- Rust (`npm run test:rust`): крипто (неверный пароль, порча шифротекста, чужой ключ,
  подмена AAD, смена пароля), миграции, CRUD, поиск, бэкап и восстановление, проверка,
  что в файле БД нет открытого текста. Бенчмарки — `#[ignore]`-тесты `kdf_benchmark`
  и `large_vault_benchmark`.
- Vitest + RTL (`npm test`): экраны и сценарии поверх фейкового бэкенда
  `src/dev/mockBackend.ts`, логика (форматирование, оценка пароля, Markdown-правки).
- Playwright (`npm run e2e`): основные сценарии в системном Edge против dev-сервера
  с тем же фейковым бэкендом. Фейковый бэкенд подключается только в dev-режиме вне
  Tauri и в релизную сборку не попадает.
- Ручная проверка настоящего приложения: debug-сборка читает папку данных из
  `NEXUS_VAULT_DATA_DIR`, чтобы не трогать настоящее хранилище. Такая тестовая копия
  не занимает блокировку «один экземпляр» и глобальную клавишу, поэтому ярлык всегда
  открывает настоящее приложение. Чтобы запустить её рядом с настоящим, нужна и своя
  папка WebView2: `WEBVIEW2_USER_DATA_FOLDER`.

## 8. Производительность

Замеры на Ryzen 5 2600 / 16 ГБ, релизная сборка:

| Что                                  | Цель     | Факт                                      |
| ------------------------------------ | -------- | ----------------------------------------- |
| Холодный запуск (окно с интерфейсом) | < 2 с    | ≈ 0,8 с (первый запуск ОС — 1,7 с)        |
| Поиск по 10 000 записей              | < 300 мс | ≈ 7 мс                                    |
| Список 10 000 записей с сортировкой  | —        | ≈ 30 мс                                   |
| Расшифровка 10 000 записей при входе | —        | ≈ 50 мс (+ 0,7 с Argon2id)                |
| Память в простое                     | ≈ 150 МБ | ≈ 165 МБ: Rust 6 МБ, остальное — WebView2 |

Память почти целиком занимает движок WebView2 (6 процессов Edge); само приложение
уменьшить её заметно не может.

## 9. Сборка и CI

npm + `package-lock.json`, `Cargo.lock` в репозитории. Релиз —
`scripts/build-release.ps1`: подключает `tauri.release.conf.json`
(`createUpdaterArtifacts`), подписывает установщик ключом из `%USERPROFILE%\.tauri` и
пишет `latest.json`. Приложение берёт его по адресу
`github.com/STANFORDVIBE/nexus-vault/releases/latest/download/latest.json`.
Строки установщика — `src-tauri/nsis/Russian.nsh`. GitHub Actions на `windows-latest`:
lint, typecheck, Vitest, `cargo clippy`, `cargo test`, сборка установщика (NSIS).
