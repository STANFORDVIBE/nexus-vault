# Nexus Vault — безопасность

Что защищает приложение, как именно и где его пределы. Документ честный: если что-то
не защищено, это написано прямо.

> Независимого аудита кода и криптографии пока не было. Используются только проверенные
> крейты RustCrypto, но сама схема и код приложения внешне не проверялись.

## От чего защищает

| Угроза                                                 | Защита                                                                                                                                                                         |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Кража файла `vault.db` или резервной копии `.nexus`    | Всё содержимое зашифровано; без мастер-пароля — только перебор через Argon2id                                                                                                  |
| Перебор мастер-пароля по украденному файлу             | Argon2id, 256 МиБ памяти, 3 прохода: каждая попытка ≈ 0,7 с и 256 МиБ RAM                                                                                                      |
| Подмена или перестановка зашифрованных записей в файле | AEAD с привязкой к id хранилища, записи и типу — подмена даёт ошибку расшифровки                                                                                               |
| Ослабление параметров KDF в файле                      | Параметры проверяются на минимумы при каждом открытии                                                                                                                          |
| XSS / вредоносный текст в заметке                      | Строгий CSP, Markdown без HTML; картинки — только свои зашифрованные (PNG/JPEG/WebP/GIF по сигнатуре, без SVG и внешних адресов); ссылки открываются только http(s) через Rust |
| Подглядывание в незаблокированный компьютер            | Автоблокировка по бездействию, при блокировке Windows, при закрытии окна                                                                                                       |
| Пароль, забытый в буфере обмена                        | Автоочистка (по умолчанию 30 с), исключение из журнала Win+V и облачной синхронизации                                                                                          |
| Утечка в сеть                                          | Нет облака, телеметрии и иконок сайтов; в сеть уходит запрос версии на GitHub и, только по кнопке, 5 символов хеша на проверку утечек                                          |
| Подменённое обновление                                 | Установщик проверяется подписью (minisign); открытый ключ вшит в приложение                                                                                                    |

## От чего НЕ защищает

- **Вредонос на компьютере** с правами пользователя: кейлоггер перехватит мастер-пароль,
  а в разблокированном состоянии ключи находятся в памяти процесса.
- **Слабый мастер-пароль.** Argon2id замедляет перебор, но не спасает пароль из словаря.
  Подбор через само приложение тормозится паузой после трёх неверных попыток подряд
  (2, 4, 8 … до 60 с); перезапуск приложения паузу сбрасывает, перебору по украденному
  файлу она не мешает.
- **2FA в том же хранилище.** Если хранить ключ 2FA рядом с паролем, то тот, кто открыл
  хранилище, получит оба фактора. Удобно, но для самых важных аккаунтов надёжнее
  отдельное приложение-аутентификатор.
- **Забытый мастер-пароль.** Восстановления нет и не будет — это свойство, а не баг.
- **Форензика памяти.** Ключи и расшифрованные данные затираются (`zeroize`) при
  блокировке, но гарантировать отсутствие копий нельзя: строки в JavaScript не
  затираются, ОС может сбросить память в файл подкачки или гибернации.
- **Доступ к учётной записи Windows** при включённом Windows Hello: кто знает PIN или
  может войти в эту учётную запись на этом компьютере, тот откроет и хранилище.
- **Метаданные.** В открытом виде лежат: количество записей, их типы (пароль, заметка, карта, документ),
  даты создания и изменения, признак «избранное», принадлежность к папке (но не её имя).

## Криптография

```
мастер-пароль ──Argon2id(salt 16 Б, 256 МиБ, t=3, p=4)──► KEK (32 Б)
KEK ──XChaCha20-Poly1305──► Vault Key (32 Б, случайный, хранится только в зашифрованном виде)
Vault Key ──XChaCha20-Poly1305──► каждая запись и каждое имя папки
```

- Крейты RustCrypto: `argon2`, `chacha20poly1305`; случайность — CSPRNG ОС (`getrandom`).
- Nonce — 24 случайных байта на каждое шифрование.
- AAD: `nexus-vault/v1/item/{vault_id}/{item_id}/{type}`, для папок и ключа — аналогично.
- Открытый текст перед шифрованием дополняется до кратного 64 байтам, чтобы размер
  шифротекста не выдавал точную длину пароля или заметки.
- Неверный пароль определяется ошибкой аутентификации, хеша пароля в файле нет.
- Смена мастер-пароля перешифровывает только Vault Key; данные не трогаются.
- Версии формата (`crypto_version`, `format_version`) хранятся в файле: более новый
  формат старая версия программы открыть откажется, а не испортит.

### Windows Hello

Включается вручную после ввода мастер-пароля. Для каждого хранилища Windows создаёт свою
RSA-пару (`KeyCredentialManager`, в TPM, если он есть); закрытый ключ не покидает
систему. Приложение хранит случайный challenge и Vault Key, зашифрованный ключом
`SHA-256("nexus-vault/v1/hello-kek" ‖ подпись challenge)` — подпись PKCS#1 v1.5
детерминирована, поэтому получается каждый раз заново, но только после подтверждения
лицом, отпечатком или PIN. Копия файла хранилища на другом компьютере через Hello не
откроется. Выключение удаляет и конверт, и ключ Windows.

### Параметры Argon2id

Замер на Ryzen 5 2600, 16 ГБ (`cargo test --release -- --ignored kdf_benchmark --nocapture`):

| Память  | Время  |
| ------- | ------ |
| 64 МиБ  | 0,16 с |
| 128 МиБ | 0,34 с |
| 256 МиБ | 0,70 с |
| 512 МиБ | 1,40 с |

Выбрано 256 МиБ: разблокировка укладывается в секунду и остаётся заметно выше
рекомендаций OWASP (19 МиБ, t=2).

## Граница доверия

WebView (React) считается потенциально скомпрометированным. Поэтому:

- Ключи, SQLite и криптография — только в Rust. Фронтенд вызывает около 60 явных IPC-команд.
- Пароль записи, номер карты, CVV, PIN, номер документа и скрытые свои поля не
  передаются в WebView при просмотре; копирование выполняет Rust по id записи и имени
  поля. В WebView секрет попадает только по явному «Показать» и в форму редактирования.
- Проверка паролей считается в Rust; во фронт уходят только записи, не пароли.
- Tauri capabilities минимальны: нет доступа к файловой системе, shell и сети.
  Обновления проверяет и скачивает Rust (плагин updater), WebView в сеть не ходит.
  Файлы бэкапа выбираются только через системный диалог в Rust.
- Внешние ссылки открываются через Rust и только со схемами `http`/`https`.

## Проверка утечек

Работает только по кнопке на странице «Проверка паролей». Для каждого пароля Rust
считает SHA-1 и отправляет в `api.pwnedpasswords.com/range/` первые 5 hex-символов
(k-anonymity). Сервис возвращает все известные хеши с таким началом, плюс подставные
(заголовок `Add-Padding`, чтобы размер ответа ничего не выдавал); сравнение идёт
локально. Ни пароль, ни полный хеш не покидают компьютер, WebView в сеть не ходит.

## Импорт

Файл выбирается через системный диалог и читается в Rust (не больше 50 МБ). Записи
только добавляются, существующие не меняются; совпадающие по содержимому пропускаются.
Импортируемый CSV — незашифрованный файл: после импорта его стоит удалить.

## Блокировка

Хранилище блокируется: вручную (Ctrl+L, кнопка, трей), по бездействию (по умолчанию
5 минут; активность — клики, клавиши, прокрутка), при блокировке Windows (Win+L),
при закрытии окна (по умолчанию). При блокировке:

1. Vault Key и все расшифрованные записи удаляются из памяти Rust с затиранием.
2. Если в буфере обмена наш секрет — он стирается сразу.
3. Интерфейс размонтирует все экраны с данными и показывает экран разблокировки.

## Резервные копии

Формат `.nexus`: заголовок (магия, параметры KDF, соль, зашифрованный ключ) и тело,
зашифрованное ключом хранилища; заголовок входит в AAD, его подмена обнаруживается.
Копия открывается мастер-паролем, действовавшим на момент её создания.

Восстановление сначала полностью расшифровывает и проверяет копию, затем пишет новую
базу рядом и подменяет файл; если подмена не удалась, прежний файл возвращается
на место. Текущее хранилище сохраняется как `<имя>.previous-<время>.db` — у каждого
восстановления свой файл, старые не перезаписываются.

Автокопии делаются в фоне, пока хранилище открыто (по умолчанию раз в сутки, 10 штук),
в `%APPDATA%\com.nexusvault.app\backups` или выбранную папку.

Экспорт в CSV/JSON — **незашифрованный**: требует мастер-пароль и предупреждает об этом.

## Где лежат данные

- `%APPDATA%\com.nexusvault.app\vault.db` — основное хранилище (SQLite, `secure_delete`);
  новые хранилища — в `vaults\`, список — `vaults.json` (имена и пути, без секретов).
- Забытое хранилище при сбросе не удаляется, а переименовывается в `*.forgotten-<время>`.
- `%LOCALAPPDATA%\com.nexusvault.app\` — служебные данные WebView2 (без секретов).
- В `localStorage` WebView — только тема, сортировка и настройки генератора.
